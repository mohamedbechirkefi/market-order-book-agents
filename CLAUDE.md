## 2. Mandatory requirements (master prompt section 11)

- **Registry first.** Every experiment is registered in `research/experiment_registry.csv` with a stable EXP id before confirmatory execution: purpose, dependency, primary outcome, protocol hash, status, report location, planned analysis. A seed is a run inside an experiment, not a new experiment. A new question or materially different protocol gets a new id.
- **Protocol before execution.** `research/experiments/EXP-NNN/protocol.md` follows section 11.2. Confirmatory runs only after the owner freezes it and its hash is recorded. Post-hoc changes are dated, justified and exploratory.
- **One standalone report per registered experiment** (`report.md`, section 11.3 structure, twelve parts), including failed, null, abandoned and exploratory ones, linked to its own `config.json`, `run_manifest.json`, `metrics.csv`, `figures/` and `reproduction.md`. Tables and figures are generated from actual outputs, never copied by hand or mocked.
- **One integrated manuscript** `research/paper/manuscript.md` (section 11.4 structure). Markdown is canonical; `manuscript.tex` is generated by pandoc; PDFs by pandoc to Typst and the `typst` Python package (D-003). Never claim a PDF exists that was not generated and inspected.
- **Evidence pipeline** (11.5): one generator for tables and figures, reused by reports, manuscript, demo and articles; a manifest maps every number to EXP id, run ids, metric, result path, script, config/protocol hash and code revision. A second review pass challenges the preferred hypothesis.
- **Milestone additions** (11.6): M0/M1 registry, skeleton and protocols; M2 schemas, manifests and report generators with the core; M3 reports as experiments finish; M4 evidence audit and manuscript; M5 identical results across demo, paper and articles; M6 PDFs inspected, clean-clone reproduction, owner review checklist.
- **Publication package** (11.7) is prepared, never released, without owner approval.
- Update `roadmap.md` and append to `progress.md` after every milestone and before ending each session, with commands and their real outputs. Never mark incomplete work done.
